# 운영 중 배포 점검

## 배포 전

- [ ] 새 셋업 요청을 중지하고 작업이 더 생기지 않도록 운영 담당자와 조율한다. 점검은 순간 상태이므로 배포 직전 다시 확인한다.
- [ ] 관리자 PC 화면의 배포 가능 여부와 `./manage.sh deploy-check`를 확인한다. 진행 중·대기·복구 대기 작업이 모두 0건이어야 한다. `DUCT_DEPLOY_URL`은 서버 URL, `DUCT_ADMIN_TOKEN`은 관리자 토큰이다. 실패 또는 대기 필요이면 중단한다.
- [ ] 모든 PC의 `Config/ActiveJob.json`이 없는지 확인한다. 보고하지 않는 구버전·오프라인 PC도 직접 확인한다. API의 확인 불가 항목을 해소한다.
- [ ] DB와 설정 및 제품 키 복구에 필요한 vault 키를 백업하고 복원 가능 여부를 확인한다.
- [ ] 현재 실행 이미지와 롤백할 이미지 태그를 기록한다.

## 배포

- [ ] 서버를 먼저 배포한다. 이후 각 PC의 진행 작업이 없을 때 최신 ZIP을 받아 압축 해제 후 InstallAgent.bat을 한 번 실행한다. 이전에 받은 ZIP은 폐기한다.

## 배포 후

- [ ] health와 `/admin` 로그인, 관리자 PC 상태를 확인한다.
- [ ] ZIP 압축 해제 후 최상위의 InstallAgent.bat, CollectDiagnostics.bat, 시작 안내.txt 3개를 확인한다.
- [ ] 키 동기화 API와 다운로드 ZIP의 Config/PackageVersion.txt 및 화면 표시 버전을 확인한다.
- [ ] PC가 새 패키지 버전을 보고하는지 확인하고 작업을 재개한다.

## 롤백

- [ ] 신규 요청을 중지하고 작업과 ActiveJob을 다시 확인한다. 진행 중 작업이 있으면 종료·복구 확인 후 진행한다.
- [ ] 기록한 이전 이미지 태그로 서버를 복구한다. DB·설정 복원은 백업과 버전 호환성을 확인하고 필요한 경우에만 수행한다.
- [ ] health, 관리자 로그인, 키 동기화 및 PC 연결 상태를 확인하고 담당자에게 결과를 알린 뒤 작업을 재개한다. 에이전트 호환성도 확인한다.
