# 한컴 VC++ 런타임 충돌 복구

## 확인한 현상과 변경

2026-10-14 클라이언트 로그: Office 정상으로 제거/설치를 건너뛰었고, 한컴 모듈에서 첫 PROCESS_EXIT: 1638 후 중단됐다. 클라이언트에는 VC++ v14 x86/x64 14.50.35719가 설치되어 있다. 서버의 실제 VC_redist.x86.exe 제품 버전은 14.29.30037.0으로 확인했다. 기존 런타임과의 충돌 가능성이 높지만 이전 로그에는 실행 대상 구분이 없어 확정할 수 없다.

Common.ps1의 런타임 도우미는 배포 실행 파일의 제품 버전과 Windows의 VC v14 x86 등록(Installed=1, Version)을 비교한다. x64만으로는 x86 요구를 충족한 것으로 보지 않는다. 같은 v14 계열이고 원본 이상인 x86 버전이 확인되면 런타임 설치를 건너뛴다. 누락·구버전·잘못된 등록은 설치를 시도한다.

1638 또는 HRESULT 0x80070666(-2147023258)이면 등록을 다시 확인하고 호환 버전을 확인한 경우에만 계속한다. 확인할 수 없으면 VC_RUNTIME_CONFLICT로 중단한다. 다른 설치 실패 코드는 유지하며 3010 재부팅 필요 코드도 보존한다. 원본 제품 버전을 읽지 못하면 기존 설치를 임의로 호환 판정하지 않는다.

한컴 모듈은 기존 한컴 제거, VC++ x86 런타임, 한컴 MSI 시작을 별도 로그로 남긴다. 명령줄과 제품 키는 기록하지 않는다. 이번 수정은 설치 모듈과 공통 도우미이며 연결 루프 Agent.ps1은 변경하지 않는다. 기존 설치기 프로세스 정리 방식과 설치 후 검증 개선은 V2_PLAN.md 후속 범위다.

## 클라이언트 업데이트와 재시도

1. 실패한 설치 프로세스가 끝났고 진행 중/결과 미전송 작업이 없는지 확인한다. ActiveJob.json이 남았다고 임의 삭제하지 않는다.
2. 업데이트된 서버의 HTTPS 주소로 접속해 최신 에이전트 ZIP 전체를 내려받고 압축 해제한다. 서버가 다른 체크아웃이면 이 변경을 반영한 뒤 내려받아야 한다.
3. Config/ServerUrl.txt에 서버의 HTTPS 기본 주소만 있는지 확인한다. /admin, /client, 인증 fragment는 넣지 않는다.
4. InstallAgent.bat을 관리자 권한으로 실행한다. 기존 등록을 미리 해제하거나 ProgramData 폴더를 삭제할 필요는 없다. 이미 서버 등록을 삭제한 PC는 다시 등록하고 관리자 승인을 받는다.
5. 관리자 화면에서 연결과 최신 상태를 확인한 뒤 셋업을 요청한다. 이번 도구는 한컴만 재시도하는 새 기능을 제공하지 않는다. Office 탐지가 정상이라면 기존 Office 단계는 건너뛴다. 탐지 상태가 바뀌면 제거/설치가 실행될 수 있으므로 요청 전 상태를 확인한다.
6. 로그에서 VC++ x86 호환 런타임 확인/설치 건너뜀과 한컴 MSI 설치 시작을 확인하고 실제 제품 설치 결과를 확인한다. 설치 완료와 라이선스 인증은 별도로 확인한다.

작업 로그: C:\ProgramData\DuctTapeAgent\logs\<작업ID>.out.log 및 .err.log. Deployment.log는 실행 계정의 실제 TEMP/duct-tape에 저장되므로 C:\Windows\Temp로 고정할 수 없다.

## 검증과 후속 작업

- Windows PowerShell 5.1: Test-VcRuntime.ps1의 누락/구버전/잘못된 등록, 동등/최신 버전, 두 충돌 코드의 확인 성공/실패, 원본 버전 미확인, 1603, 3010 모의 테스트 통과.
- Test-Common.ps1: 전체 모듈 구문, 키/INI 사전 검사, 모의 한컴 설치, 최신 x86 런타임 건너뛰기 후 MSI 실행, 키 비노출·재부팅 상태 검증 통과.
- 실제 배포 VC++ 실행 파일의 제품 버전을 읽기만 했으며 설치기를 실행하지 않았다. 실제 클라이언트의 한컴 설치 성공 여부는 업데이트 후 현장 확인이 필요하다.
- Python 공개 패키지/앱 원본 및 작업 큐 회귀 테스트 14개 통과. 최초 샌드박스 실행은 대기해 중단했고 로컬 테스트 환경에서 완료했다.
- 후속: 실패 단계별 원인 수집, 안전한 앱별 재시도, 설치 후 검증, 프로세스 정리 범위 개선. 손상된 런타임까지 버전 등록만으로 검증할 수는 없다.
