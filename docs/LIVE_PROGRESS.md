# 실제 셋업 진행 내역

작업 시작 버튼을 누르면 요청 접수부터 다운로드·압축 해제·파일 배치·서버 통신·앱별 모듈 실행·최종 결과를 관리자와 클라이언트 화면에서 확인한다. 단일 회전 아이콘 대신 CLI처럼 단계별 진행/완료/실패 내역을 누적 표시한다.

## 실제로 측정하는 값

- 다운로드: HTTP 스트림에서 받은 바이트 수와 Content-Length. 받은 MB/전체 MB·현재 다운로드 비율을 표시한다. 전체 크기가 없으면 받은 양만 표시한다.
- 압축 해제: 실제 처리한 ZIP 항목 수/전체 항목 수.
- 실행 단계: 공통/앱 모듈 완료 수/실제 실행 계획의 모듈 수. 동일한 시간 가중치로 전체 설치 백분율을 계산하지 않는다.
- 설치기: 현재 실행 모듈, 시작/완료/실패 및 경과 시간. ODT/MSI 내부 설치 백분율은 계측하지 않으므로 표시하지 않는다.
- 연결: 실행 도구 인수 대기와 실행 중 응답 시각을 구분한다. 설치 중 단계 변화가 없어도 에이전트 heartbeat로 응답을 확인한다.

## 전달 구조

JobProgress.ps1이 고정 단계·검토한 모듈명·수치만 JSONL로 기록한다. DUCT_JOB_ID는 해당 작업의 자식 프로세스에만 전달한다. Agent.ps1은 약 2초마다 새 기록을 전송하고 10초마다 heartbeat를 유지한다. ProgressDelivery.ps1은 확인된 순서 번호 이후 기록만 전송하며 실패 시 다음 전송에서 다시 시도한다.

서버 job_progress 테이블은 작업/순서 번호로 중복을 차단한다. 관리자와 해당 PC만 이력을 조회하고 해당 에이전트만 기록한다. 자유 형식 메시지·원문 예외·설치 명령줄·stdout·키를 받지 않는다. 진행 내역 보고에 실패해도 실제 설치 결과의 전송은 별도로 유지한다.

화면은 선택한 PC의 최신 작업을 증분 조회하고 작업 중 약 2초 간격으로 갱신한다. 시간이 필요한 설치 단계는 경과 시간이 늘어난다. 숫자 막대는 단계별 실제 수치이며 전체 작업의 예상 완료율이 아니다. 갱신 실패 시 마지막 기록을 유지하고 오류 안내를 표시한다.

## 적용

서버에는 코드와 DB 테이블 초기화가 필요하다. 클라이언트는 최신 실행 도구 ZIP을 받아 InstallAgent.bat을 다시 실행해 복구/업데이트한다. 실행/대기/중단 확인 작업이 있을 때는 도구가 갱신을 막으므로 해당 작업이 끝난 후 적용한다. 기존 도구는 최근 01~06 단계 보고와 최종 상태를 표시한다. 새 이벤트가 없으면 상세 수치 미지원 안내를 표시한다. 서버 재연결 뒤 같은 실행 중 프로세스의 heartbeat는 상태를 회복할 수 있지만 작업을 재claim하거나 설치를 재실행하지 않는다.

## 검증

- test_job_progress.py: 권한, 수치 검증, 재전송, 순서 충돌, 증분 조회와 종료 상태.
- test_portal.py 및 test_admin_browser.py: 실제 수치·단계·경과·완료 갱신과 기존 관리자 기능.
- Test-JobProgress.ps1: 실제 JSONL 생성과 전송 확인·오프라인 재시도.
- test_progress_download.py: 실제 로컬 HTTP 바이트 다운로드와 크기 검증·리다이렉트 차단.
- 기존 ZIP 준비·앱 실행 순서·Office 키 주입 테스트도 유지한다.

실제 Windows 제품 설치는 별도 PC에서 확인한다. 설치기의 원문 로그를 브라우저에 공개하거나 설치가 없는 상태에서 가짜 백분율을 만들지 않는다.
