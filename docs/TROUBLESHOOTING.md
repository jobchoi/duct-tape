# 문제 해결 및 보존할 현장 이력

사용자 제공 현장 이력과 저장소 정적 검토를 구분합니다. Phase 1에서는 Windows 설치를 실행하지 않았습니다. 아래 대응이 모든 환경의 해결을 보장하지는 않습니다.

## 한컴 GUI 팝업

- 현장 이력: 외부 런처를 숨겨도 GUI가 노출되어 setup.ini의 `LevelOption=1`과 내부 MSI 직접 설치를 사용했습니다.
- 현재 코드: 06은 `Hancom\Install\Hwp130.msi`를 `/qn AGREETOLICENSE=yes PIDKEY=... /norestart`로 실행합니다. INI 자동 수정은 없습니다.
- 대응: 매체의 setup.ini에서 LevelOption=1을 확인하고 내부 MSI와 부속 파일을 보존합니다. 백업 스크립트의 Install.exe 방식은 표준 진입점에서 사용하지 않습니다.
- Phase 2 검증: 매체에 맞는 INI 위치·인코딩·섹션을 확인해 처리를 추가합니다. 읽기 전용 SMB와 동시 실행을 고려해 쓰기 위치를 결정하고 테스트 기기에서 GUI 미노출을 확인합니다.

## 한컴 1603 방어

- 현장 이력: 잔존 설치 프로세스 종료, 구버전 제거, VC++ x86 선행 설치를 방어 조치로 사용했습니다.
- 현재 순서: Install/setup/msiexec 강제 종료 → 구버전 제거 → VC++ x86 `/install /quiet /norestart` → 키 로드 → MSI 설치. 0과 3010은 현재 성공으로 처리합니다.
- 대응: 다른 설치 작업, 관리자 권한, 매체 접근, 런타임·제거 결과, 재부팅 필요 여부를 확인합니다. 1603만으로 키 오류를 단정하지 않습니다. `C:\Windows\Temp\HancomMSIInstall.log`의 실패 직전 문맥을 현장에서 확인합니다.
- 상세 로그에 PIDKEY가 포함될 수 있으므로 원문을 Git·관제·외부 문의에 첨부하지 않습니다. 공유 전 비밀값을 제거합니다.
- Phase 2 보완: 키·매체 사전 검증, VC++/제거 종료 코드 처리, 재부팅 필요 상태 구분 및 비밀값 로깅 검증. 다른 배포 작업에 영향을 줄 수 있는 강제 종료는 테스트 시간대를 분리해 검증합니다.

## UNC 경로 유실

- 현장 이력: `$MyInvocation` 대신 `$PSScriptRoot`의 부모를 DeployRoot로 계산해 대응했습니다.
- 현재 코드: Main.bat은 pushd를 사용하고 상태 파일은 `%TEMP%\Tapbook_State.json`에 둡니다. 03과 백업 스크립트에는 이전 경로 계산이 남아 있습니다.
- 대응: 관리자 실행 계정의 공유 접근 권한, Office setup.exe/XML 및 한컴 MSI의 위치를 확인합니다. 공백 포함 경로는 따옴표로 감싸며 HTTP 주소를 실행 경로로 전달하지 않습니다.
- Phase 2 검증: 로컬·USB·UNC 및 공백/한글 폴더에서 같은 루트를 계산하는지 확인하고 호출부와 모듈의 상태 파일 경로를 일치시킵니다.

## 네트워크 파일 보안 경고

- 현장 이력: Unblock-File로 파일 차단 표시로 인한 경고에 대응했습니다.
- 현재 코드: 01이 배포 루트를 재귀 탐색해 실행하고 실패는 무시합니다.
- 대응: 신뢰할 수 있는 기관 매체인지 확인한 뒤 차단 해제 결과와 공유 파일 수정 권한을 점검합니다. 읽기 전용 공유는 배포 준비 단계에서 처리하거나 쓰기 가능한 로컬 복사본을 사용합니다.
- 제한: 모든 실행 정책·보안 정책·SmartScreen 경고 해제를 보장하지 않습니다. 정책 일괄 비활성화로 대체하지 않습니다.
- Phase 2 검증: 실제 네트워크 기기에서 차단 해제 성공·실패와 안내를 확인합니다.

## 키 누락 및 저장소 노출

현재 06은 구버전을 제거한 뒤 키 파일을 확인하므로 키 누락 시 기존 설치가 이미 제거되었을 수 있습니다. 실행 전에 Config/HancomKey.txt를 준비하고 예제 값을 실제 키로 바꿉니다. 사전 안전 종료 계약은 [아키텍처](ARCHITECTURE.md)에 있습니다.

Phase 1에서 추적 중인 `Modules/backup_1_06_InstallHancom.ps1` 주석의 키 형식 문자열을 발견해 값만 제거했습니다. 실제 키 여부는 확인하지 않았습니다. Git 이력은 그대로이므로 기관 담당자가 유효성과 교체 필요성을 확인해야 합니다. 이력 재작성은 별도 승인 후 수행합니다. ignore는 과거 이력이나 이미 추적 중인 파일을 정리하지 않습니다.
