# 환경 셋업 기획 — 로컬 테스트 기준

## 현재 목표

클라이언트가 웹에서 실행 도구를 받고 한 번 설치하면 서버에 자동 연결 신청한다. 서버는 PC 중복 여부를 확인하고, 클라이언트는 환경 셋업 버튼 하나로 요청한다. 관리자는 연결된 PC와 진행 상태를 확인한다.

## 기본 사용자 흐름

1. `/client`에서 실행 도구 ZIP을 다운로드하고 압축을 푼다.
2. `InstallAgent.bat`을 실행해 관리자 권한을 승인한다. 서버 주소는 다운로드 패키지에 포함한다.
3. 설치가 완료되면 바탕화면 바로가기가 생성되고 웹 페이지가 열린다.
4. Office·한컴 매체와 기관 라이선스 키가 준비된 PC만 셋업을 시작한다. 없으면 필요한 준비를 명확히 표시한다.
5. 관리자는 `/admin`에서 실제 연결된 PC를 선택하고 상태를 확인하거나 셋업을 요청한다.

## 로컬 테스트에서 간소화하는 항목

- `DUCT_AUTH_MODE=development`일 때 관리자 인증 키 입력과 PC 승인 절차를 생략한다.
- 클라이언트는 토큰 대신 Windows MachineGuid를 사용한다. PC 이름은 표시와 중복 진단에 사용한다. 이름 변경/동일 이름 때문에 잘못된 PC로 합치지 않도록 식별 키와 표시 이름을 구분한다. MAC은 어댑터 변경과 복제 문제로 기본 식별 키로 사용하지 않는다.
- 같은 PC 식별값으로 다시 신청하면 연결을 중복 생성하지 않는다. 최초 연결 요청을 승인 상태로 처리한다.
- 등록 코드, 수동 토큰 교환, 설치 종류/학년 등 선택 옵션을 기본 화면에서 제외한다.
- 더미 보고와 실행 도구가 없는 PC는 실제 작업 대상에 포함하지 않는다.

식별값은 인증 수단이 아니다. 이 모드는 현재 승인된 로컬 테스트용이며 운영 모드의 기본값은 `secure`다. 운영 전에는 인증 모드를 전환하고 HTTPS·PC별 인증·승인 정책을 적용한다.

## 구조

- Model: PC 식별/중복, 매체 준비 여부, 작업 큐와 상태 전이.
- Controller: 연결 신청, 실행 도구 다운로드, 상태 조회와 셋업 요청.
- View: 다운로드/최초 설치와 PC별 셋업 화면, 관리자 상태 화면.
- SecurityPolicy: development/secure 정책을 분리한다. 업무 로직에서 인증 방식에 의존하지 않도록 유지한다.
- Windows 실행 도구: 고정된 보고/셋업만 실행하고 임의 명령은 받지 않는다.

## 완료 기준

다운로드 ZIP에 실제 실행 파일이 들어 있고 비밀정보가 없어야 한다. 설치는 Office 매체가 없어도 PC 연결과 바로가기 생성까지 가능해야 한다. 매체가 없으면 셋업 시작을 막고 이유를 표시해야 한다. 관리자 화면은 로그인/테스트 모드/연결 상태를 분명하게 표시해야 한다. 연결 신청·중복 신청·매체 준비·셋업 요청·단일 claim·결과 보고를 자동 테스트하며 실제 HTTP 및 PowerShell 보고 경로도 확인한다.

## 이후로 미루는 항목

선택 설치, 학교별 옵션, 자동 매체 배포, 고급 권한/SSO, 이력 분석은 기본 흐름이 Windows 테스트 PC에서 검증된 후 별도로 기획한다. Windows UAC·예약 작업·실제 ODT/MSI 설치는 실제 PC 인수 테스트가 필요하다.
