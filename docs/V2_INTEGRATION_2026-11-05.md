# v2 기능 브랜치 통합 기록 — 2026-11-05

사용자 선택: `feature/v2-mdm-ui`의 후속 검증 후 `develop`에 병합하고 기능 브랜치를 삭제한다. 운영 `main`, `v1.0.0-rc.1`, Pi 실행 이미지는 변경하지 않는다. 현장 미검증 과제가 남아 있으므로 이번 통합을 v2 정식 운영 배포로 간주하지 않는다.

## 후속으로 확인한 사항

관리자 브라우저 회귀 시험에 실패 후 재시도 흐름을 추가했다. 모의 에이전트로 완료 작업 이후 새 작업 실패 → 시작 버튼 재활성화 → 등록/승인 삭제 없이 재요청 → 다른 작업 ID 및 활성 작업 1개 → 완료를 확인한다. 실물 PC의 설치기를 실행하지 않는다. 시험 서버는 임시 DB/가짜 매체 경로만 사용하도록 명시했다.

기존 코드에서 이 흐름은 통과했다. 따라서 원인이 확인되지 않은 현장 ‘버튼 무반응’을 해결한 것으로 기록하거나 불필요한 UI 변경을 추가하지 않는다.

## 검증 결과

- 전체 Python 대상 123개를 분할 확인: 117개 통과, 6개 선택 실행 항목 건너뜀. 일괄 실행은 240초 제한에서 결과 116개(통과 110/건너뜀 6)까지 확인했고, 마지막 동시성 시험을 포함해 2개를 겹친 나머지 9개를 재실행하여 전부 통과했다(27.96초). 일괄 실행 한 번이 정상 종료된 것으로 기록하지 않는다.
- 실제 Chromium: 관리자/진행/실패 재시도·v2 앱 등록/선택/결과·QR 다운로드/독립 디코딩/기능 토글, 3 passed(85.08초).
- 별도 Blogger CLI 환경의 오프라인 unittest: 14 passed(23.380초), 외부 업로드 없음. 전체 Python 시험과 중복될 수 있으므로 단순 합산하지 않는다.
- 문서 링크·git diff 형식·변경한 Python 구문 검사.
- FastAPI TestClient/httpx 사용 중단 예정 경고는 기존 의존성에서 발생한다. 이번에 임의 의존성 업그레이드는 하지 않았다.

### 실행 환경과 제한

처음 전체 시험은 서버용 .venv에서 Blogger의 선택 의존성(bleach 등)이 없어 해당 테스트가 실패했다. Blogger는 별도 .venv-blog에서 오프라인 시험을 통과했다. 전체 시험용 임시 환경에는 Server/requirements-dev.txt와 tools/blogger/requirements.txt를 함께 설치했다.

현재 Conda Python 3.13.12/SQLite 3.51.1에서 동시 보고 시험이 DB close 구간에서 정체되어 시간 제한으로 종료했다. 캐시 비활성화 실험도 해결하지 못해 변경을 되돌렸다. Ubuntu 기본 Python 3.12.3/SQLite 3.45.1에서는 같은 최소 동시 쓰기 시험이 통과했다. 전체 비교 검증은 `/tmp/duct-v2-verify` 독립 환경에서 수행한다. OS의 venv/ensurepip 패키지가 없어 OS 설치를 바꾸는 대신 기존 pip의 `--python` 기능으로 임시 환경 의존성을 준비했다.

이 비교만으로 CPython 전체·SQLite 일반·운영 Pi의 결함이라고 단정하지 않는다. DB 코드를 추측으로 바꾸지 않았으며 Conda 환경의 근본 원인은 미확정이다. 새 환경에서 실제 Python/SQLite 버전과 동시 시험을 확인한다.
