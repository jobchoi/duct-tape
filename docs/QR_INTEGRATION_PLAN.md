# 관리자 QR 도구 통합 검토

기준일: 2026-10-21. 참고 파일: `refernces/qr.py`, `refernces/pad_qr.py`. 사용자가 옮긴 경로는 references가 아닌 refernces다. 원본은 수정하거나 실행하지 않았다. 파일에 import 시 실행되는 작업이 있어 실행 대신 소스만 검토했다. 이 문서는 제안이며 QR 웹 기능은 아직 구현하지 않았다.

## 확인한 기존 동작

| 파일 | 입력 | QR에 담는 값 | 출력/특징 |
| --- | --- | --- | --- |
| qr.py | data.csv, 이름·S/N 열, 연도/이름/라벨 위치 콘솔 입력 | 연도\|이름\|시리얼 | A4 14칸 PDF, 왼쪽 열 1~7번 후 오른쪽 8~14번 |
| pad_qr.py | data.xlsx, user·serial 열 | 시리얼 | A4 14칸 PDF, 행 순서로 좌우 배치 |

두 파일 모두 Formtec 3108 라벨 출력을 의도하지만 여백과 번호 순서가 다르다. 실제 용지 인쇄 정렬은 검증하지 않았다. qr.py는 Windows 맑은 고딕 경로에 의존하고 다른 OS에서는 Helvetica로 대체하므로 한글 출력이 보장되지 않는다. pad_qr.py는 pandas/Excel 엔진 등 의존성이 있고 QR 임시 PNG의 삭제 처리가 없다. qr.py의 단순 split 방식은 따옴표가 있는 CSV를 정확히 처리하지 못하며 잘못된 인코딩을 무시한다. 웹 통합 시 원본을 그대로 import/실행하지 않는다.

## 권장 화면

관리자 상단 **도구 → QR 생성**(`/admin/tools/qr`)으로 분리한다. PC 셋업 작업 큐·에이전트 설치 기능과 섞지 않는다. QR 생성에는 클라이언트 에이전트가 필요 없다.

첫 화면은 **QR에 넣을 값 입력 → 생성 → 미리보기 → 이미지 다운로드**만 제공한다. 시리얼·URL·일반 텍스트를 입력할 수 있게 하되 내용을 자동으로 URL에 접속해 검증하지 않는다. 기본값은 입력한 문자열 그대로이며 이름·연도 등 개인정보를 자동으로 붙이지 않는다. 관리자 PC 목록의 '시리얼로 QR 만들기'는 이후 같은 화면을 여는 편의 기능으로 연결할 수 있다.

기존 인쇄 도구는 별도 **라벨 PDF 만들기** 탭/접힌 영역으로 추가한다. CSV 명단 업로드와 항목 미리보기, 전체/선택 출력, 시작 위치(1~14), A4 14칸 템플릿을 제공하는 후속 범위로 둔다. Excel 지원과 세부 여백 조정은 필요할 때 추가한다. 기존 두 형식 중 어떤 QR 값을 이어갈지 확인 없이 연도·이름·시리얼 형식으로 통일하지 않는다. 실제 라벨지에 일반 용지 시험 출력 후 정렬을 확인한다.

## MVC와 배포

- Model: 입력 길이/QR 용량 검증, 순수 QR 생성, 후속 CSV 파싱·PDF 배치. 서버 디렉터리나 고정 파일명에 의존하지 않는다.
- Controller: 관리자 인증, 크기/행 수 제한, 생성 결과 응답. 입력 내용은 로그·DB에 저장하지 않으며 다운로드 응답은 no-store로 제공한다.
- View: 입력, 미리보기, 오류, 다운로드. 불필요한 패키지/폰트 설정을 사용자 화면에 노출하지 않는다.
- 라즈베리 서버에서도 동작하도록 Windows 전용 경로를 제거한다. QR만 제공하는 1차 버전에는 pandas·Excel·PDF 라이브러리를 넣지 않는다. 라이브러리 버전과 ARM64 환경은 구현 시 확인한다.
- 라벨 PDF 확장 시 배포 가능한 한글 폰트와 폰트 라이선스, QR 여백 및 스캔 가능성을 검증한다. Windows 폰트를 임의로 저장소/이미지에 복사하지 않는다.

## 구현 전 확인 및 테스트

기본값 문자열 그대로 QR을 만들고 실제 스캐너로 동일 값이 읽히는지 확인한다. 인증 없는 요청 거부, 빈 값/과도한 입력, 한글·특수 문자, 미리보기·다운로드를 테스트한다. PDF 확장 시 CSV 따옴표·빈 값·시리얼 앞자리 0, 14/15개 페이지 전환, 라벨 위치 중복/범위, 한글 출력과 실제 인쇄를 별도 확인한다.
