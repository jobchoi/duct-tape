# 관리자 진행 상태 UX 검토

2026-10-21 사용자 현장 보고: Pi에서 Office 설치 기능을 사용 중이며 완료/진행 중 텍스트만으로 상태 파악이 어렵다. 실제 Pi 화면·실행 버전·로그를 이번에 조회하지 않았으므로 원인을 단정하지 않는다. 저장소에는 선택 PC의 진행 패널 코드가 있지만 현장에 동일하게 배포됐거나 모든 작업의 세부 이벤트가 수신된다고 보장하지 않는다. 이번 문서는 의견이며 진행 UI를 새로 구현하지 않았다.

## 제안

상단에 전체/진행 중/확인 필요/완료 대수를 표시하고 목록 필터로 연결한다. PC별 행은 PC 이름·시리얼, 상태 배지, 현재 단계, 단계별 진행률 또는 경과 시간, 마지막 응답을 표시한다. 행을 선택하면 상세 이벤트/오류/다음 조치를 펼친다. 작업 목록은 하나를 선택했을 때만 다른 PC 상황이 보이는 구조를 피하고 선택은 갱신 중에도 유지한다.

예: 다운로드 47% · 540/1150 MB · 1.2 MB/s / Office 설치 중 · 8분 경과 / 설치 확인 중 / 완료 / 실패: 설치 종료 코드 확인 / 재부팅 필요. 예시는 UI 설계용이며 실제 측정값이 아니다.

| 상태 | 표시 제안 | 의미 |
| --- | --- | --- |
| 대기 | 회색·시계·대기 | 아직 실행하지 않음 |
| 다운로드 | 파랑·하향 화살표·실제 비율 | 받은 바이트/전체 바이트 |
| 설치 중 | 파랑·도구 아이콘·경과 시간 | 설치기가 정확한 %를 안 주면 비율을 추정하지 않음 |
| 검증 중 | 보라·체크 확인·검증 중 | 종료와 설치 확인을 구분 |
| 완료 | 초록·체크·완료 | 해당 작업 정의의 완료 기준 통과 |
| 실패/확인 필요 | 빨강·느낌표·실패 / 황색·주의·확인 필요 | 오류와 조치 설명 |
| 연결 끊김 | 회색·연결 아이콘·마지막 응답 시각 | 작업 결과와 별도 통신 상태 |

색상만으로 구분하지 않는다. 배지 텍스트·아이콘·필터를 함께 쓰고 실패 이유와 재시도 조건을 상세에 둔다. 다운로드 100%는 설치 완료가 아니며 5/6 단계는 시간의 5/6 경과가 아니다. 통신 단절도 실패/취소로 단정하지 않는다. 수동 MDM 등록은 완료로 추정하지 않는다.

## 다음 작업 제안

먼저 현장 버전과 실제 작업 이벤트 수신을 확인한다. 이후 PC별 단계 표시·상태 배지·확인 필요 필터를 우선하고, 속도·남은 시간은 충분한 전송 데이터가 있을 때 추가한다. 정보가 없는 상태는 진행률 0% 대신 '정보 수신 대기'로 구분한다. 임의 숫자로 진행바를 움직이지 않는다.
