# Office 설치 XML에 제품 키를 직접 넣지 않고 설치할 수 있을까?

DuctTape에서 Windows PC의 설치 작업을 정리하던 중, Office 제품 키를 어디에 두어야 하는지 질문이 생겼다.

한컴은 키를 읽는 파일이 있었는데 Office 쪽에는 같은 방식의 파일이 보이지 않았다. Excel 2021과 2024 이야기도 있었지만, 사용 제품을 확인하면서 현재 설치 대상은 Office LTSC Professional Plus 2024로 정리했다. Excel 단품이 아니라 Office 제품군을 설치하는 구성이다.

여기서 남은 질문은 이것이었다.

**제품 키를 설치 XML에 직접 적어 두지 않고, 별도 파일에서 읽어 설치할 수 있을까?**

## 1. XML에 값을 전달하면 되는 것 아닐까

처음에는 install.xml에 변수나 인자를 전달하는 방식으로 처리할 수 있을지 생각했다.

하지만 XML에서 외부 텍스트 파일을 읽거나 변수를 치환하는 기능이 있다고 가정할 수는 없었다. 실제로 사용자가 확인한 내용에서도 XML 자체에 그런 인자 전달 방식이 있는지 의문이 남았다.

그래서 역할을 나눴다.

XML은 설치 설정을 담고, 외부 파일에서 키를 읽어 설정에 넣는 작업은 PowerShell이 맡도록 했다.

## 2. 보관할 파일과 실행할 파일을 나눴다

제품 키는 다음 위치에서 별도로 읽도록 바꿨다.

```text
Config/
└── OfficeKey.txt

Office/
├── setup.exe
└── install.xml
```

실제 키 파일은 Git에서 제외한다. 원본 install.xml에도 실제 키를 적어 두지 않는다.

그렇다고 키 파일을 분리하는 것만으로 설치가 되는 것은 아니다. 설치기가 읽는 XML에는 결국 필요한 값이 들어가야 한다.

그래서 원본 XML을 바로 수정하는 대신, 실행할 때만 키가 들어간 임시 XML을 만들기로 했다.

```text
별도 키 파일 읽기
        ↓
원본 XML 읽기
        ↓
제품 설정에 키 추가
        ↓
임시 XML 생성
        ↓
설치기에 전달
```

## 3. 실제로는 PowerShell에서 PIDKEY를 넣었다

구현한 함수는 먼저 키 파일을 읽어 형식을 검사한다. 이어서 XML의 설치 대상이 현재 지원하는 ProPlus2024Volume 제품인지 확인한다.

그다음 Product 요소의 PIDKEY 속성에 키를 넣는다. 관련 코드의 핵심은 다음 부분이다.

```powershell
$products[0].SetAttribute('PIDKEY', $key)
$xml.Save($path)
& $Install $path
```

여기서 `$path`는 원본 파일이 아니라 새로 만든 임시 XML의 경로다. 설치기는 다음 형태로 그 파일을 받는다.

```text
setup.exe /configure "임시폴더\install.xml"
```

즉, XML이 키 파일을 직접 찾아가는 것이 아니다. **PowerShell이 키를 읽어 설치기가 사용할 XML을 완성한 뒤 넘기는 방식**이다.

## 4. 임시 파일을 만드는 것만으로 끝내지는 않았다

실행 중 임시 XML에는 실제 제품 키가 들어간다. 파일을 분리했다고 해서 키가 어디에도 나타나지 않는 것은 아니다.

그래서 임시 디렉터리의 접근 권한을 제한하고, 처리가 끝나면 finally에서 정리하도록 했다. 원본 XML과 명령줄, 프로그램 로그에 실제 키 값을 직접 적지 않는 것도 구분했다.

작업 기록에서는 이 임시 XML 생성 경로와 관련 테스트를 확인했다. 원본과 별도 키를 읽고 실행용 설정으로 조합하는 과정이 이번 변경의 핵심이었다.

## 5. 설치 설정 확인과 Excel 실행 확인은 다르다

여기까지 만들었다고 Office 작업 전체를 검증한 것은 아니다.

현재 Office 상태 확인 모듈은 Windows의 제거 프로그램 등록 정보에서 대상 제품명을 찾는다. 대상 제품이 있으면 설치를 건너뛰는 흐름이다. 이 상태만으로 Excel이 정상 실행되거나 정품 인증까지 끝났다고 볼 수는 없다.

이번 기록에서 확인한 범위는 제품 키 분리와 실행용 XML 생성·전달 경로다. 새 Windows PC에서 실제 설치하고, Excel을 실행하고, 정품 인증 상태까지 확인하는 작업은 별도로 남겨 둬야 한다.

## 정리하며

처음 질문은 ‘XML에 키를 어떻게 전달할까’였다.

실제로 바꾼 것은 값을 보관하는 파일과 설치기가 읽을 파일을 구분하는 구조였다. 키는 별도로 보관하고, 실행할 때 필요한 XML을 만들어 전달한다.

이렇게 정리하면 원본 설정에 실제 키를 계속 적어 둘 필요가 없다. 대신 임시 파일의 권한과 정리 과정도 함께 관리해야 한다.

다음 확인은 실제 PC에서의 Office 설치와 Excel 실행·인증 결과다. 설정을 만들 수 있다는 것과 설치가 정상적으로 끝났다는 것은 나눠서 기록하려고 한다.
