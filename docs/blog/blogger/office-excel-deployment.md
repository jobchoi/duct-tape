# DuctTape 개발 일지 — Office·Excel 설치 설정과 제품 키를 분리한 과정

여러 Windows PC에 프로그램을 설치하던 BAT와 PowerShell 도구를 DuctTape의 서버·에이전트 구조로 옮기고 있다. 이번 글에서는 Office와 Excel 설치를 준비하면서 실제로 확인하고 수정한 내용을 정리한다.

## Excel을 어떤 제품으로 설치할지부터 확인했다

처음에는 Excel 2021과 2024 중 어떤 버전을 설치할지, 제품 키는 어디에 두어야 하는지 질문이 있었다. 이후 사용 제품이 Office LTSC라는 점을 확인하고 현재 설치 대상을 Office LTSC Professional Plus 2024로 정리했다.

현재 설정은 Excel 단품 설치가 아니라 Office 제품군 설치다. 설치 XML의 제품 ID는 ProPlus2024Volume이며, 64비트·한국어와 PerpetualVL2024 채널을 사용한다. Excel 실행이나 라이선스 상태를 별도로 검증하는 기능까지 구현한 것은 아니다.

## XML에서 외부 키 파일을 어떻게 읽을까

처음에는 install.xml에 변수나 인자를 전달해서 제품 키를 넣을 수 있을지 생각했다. 하지만 현재 구현은 XML 자체가 외부 텍스트 파일을 읽거나 환경변수를 치환하도록 만든 방식이 아니다.

PowerShell에서 Config/OfficeKey.txt를 읽고 형식을 검사한 뒤, 원본 install.xml을 메모리에서 읽는다. 대상 제품이 ProPlus2024Volume인지 확인하고 Product의 PIDKEY 속성에 값을 넣어 실행용 임시 XML을 만든다. Office 설치기는 그 임시 XML 경로를 /configure 인자로 받는다.

원본 XML과 실행 코드는 제품 키를 직접 담지 않고, 키가 들어간 임시 디렉터리의 접근 권한을 제한한다. 작업을 마치면 finally에서 임시 디렉터리를 정리한다. 키가 설치 과정에서 전혀 존재하지 않는다는 뜻은 아니다. 실행 중 임시 XML에는 실제 키가 들어간다.

## 설치 확인·제거·설치를 모듈로 나눴다

Office 작업은 상태 확인, 제거, 설치 모듈로 나뉜다. 현재 상태 확인은 Windows 제거 프로그램 등록 정보에서 대상 Office 제품명을 찾는 방식이다. 대상 제품이 있으면 설치를 건너뛰고, 설치 필요 상태이면 제거 설정과 설치 설정을 사용하는 흐름이다.

이 판별만으로 Excel이 정상 실행되거나 정품 인증이 끝났다고 판단할 수는 없다. 또한 기존 Office의 모든 종류와 손상 상태를 자동으로 처리하는 제거 기능까지 완성한 것은 아니다. 설치기의 종료 코드와 별도로 실제 앱 실행·인증·제거 결과를 확인할 필요가 있다.

## 라즈베리 서버로 옮기며 빠진 파일을 확인했다

Raspberry Pi 서버에는 Git으로 코드를 받았지만 설치 원본과 제품 키는 별도로 옮겨야 했다. Git에서 제외한 파일은 git pull로 전달되지 않는다.

서버의 /api/config 응답에 있는 media.ready와 missing 목록으로 원본 준비 상태를 확인했다. 준비 완료는 서버가 필요한 파일을 찾았다는 의미이며, 클라이언트에서 Office 설치가 끝났거나 라이선스 인증이 성공했다는 뜻은 아니다. 실제 설치기는 Windows 클라이언트에서 실행하고, 라즈베리 서버는 작업 요청과 원본 전달·결과 관리를 담당한다.

## 검증한 내용과 아직 남은 확인

작업 기록에는 Office 키 파일 분리, 임시 PIDKEY XML 생성 경로와 관련 테스트를 확인한 내용이 남아 있다. 원본과 키를 공개 패키지에 넣지 않는 구분도 반영했다. 이 글을 작성하며 실제 키 값을 읽거나 공개하지 않았다.

다만 이번 글에서 새 Windows PC의 Office 설치부터 Excel 실행·정품 인증까지 모두 검증했다고 말할 수는 없다. 실제 설치 결과와 인증은 별도로 확인해야 한다.

운영 중인 서버의 진행 상태가 완료/진행 중 글자만으로 보인다는 피드백도 있었다. PC별 다운로드 비율, 설치 단계, 경과 시간, 오류와 다음 조치를 구분해 보여주는 방향을 검토하고 있다. 현재 현장의 이벤트 수신과 배포 버전은 추가 확인 대상이며, 새로운 진행 UI를 운영 서버에 적용한 결과로 기록하지 않는다.
