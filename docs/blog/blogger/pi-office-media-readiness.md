# 서버는 켜졌는데 Office 설치 준비는 왜 안 됐을까?

DuctTape 서버를 WSL에서 사용하다가 Raspberry Pi 5에도 올려 보기로 했다. Docker 이미지가 만들어졌고 컨테이너도 시작됐다. 상태에는 healthy가 표시됐다.

여기까지 보면 설치 작업을 바로 시작할 수 있을 것 같았다. 그런데 서버 응답에는 다른 표시가 있었다.

```json
{
  "media": {
    "ready": false
  }
}
```

**서버가 정상적으로 켜졌는데, 왜 설치 준비는 끝나지 않은 걸까?**

## 1. 서버 실행과 설치 파일 준비는 별개였다

먼저 서버 API가 응답하는지 확인했다.

```bash
curl -f http://127.0.0.1:8000/api/config
```

응답이 돌아왔고 컨테이너도 정상 실행 중이었다. 웹 서버가 시작되지 않은 상황은 아니었다.

하지만 서버가 요청을 받을 수 있다는 것과 클라이언트에 전달할 설치 파일이 준비됐다는 것은 다른 문제였다. API의 media.ready는 배포 원본의 필수 파일이 준비됐는지를 나타내는 값이었다. 함께 반환되는 missing 목록으로 어떤 파일이 빠졌는지 확인할 수 있었다.

## 2. git pull로 설치 원본까지 옮겨지는 것은 아니었다

라즈베리 서버에는 프로젝트를 Git으로 받았다. 문제는 기존 PC에서 쓰던 파일이 모두 저장소에 들어 있는 것은 아니라는 점이었다.

Office 설치 프로그램과 별도 제품 키 파일처럼 Git에서 제외한 자료는 git pull로 넘어오지 않았다. 코드는 옮겼지만 실제 설치에 필요한 자료는 별도로 준비해야 했다.

Office 작업에서는 다음 파일들을 구분해 확인했다.

```text
Office/
├── setup.exe
├── install.xml
└── remove.xml

Config/
└── OfficeKey.txt
```

이 목록이 Office 설치 원본 전체를 뜻하는 것은 아니다. 사용하는 배포 방식에 따라 추가 데이터가 필요할 수 있다. 또한 media.ready는 설정된 전체 배포 원본을 검사하는 값이므로 Office 관련 파일만 준비했다고 전체 검사가 통과한다고 가정해서는 안 된다.

## 3. 파일을 어디에 두었는지도 확인해야 했다

컨테이너에서 실행하는 서버는 호스트의 배포 원본 디렉터리를 연결해 사용했다. 따라서 파일을 프로젝트의 아무 폴더에 넣는 것으로는 충분하지 않았다. 서버가 실제로 읽는 배포 원본 경로 안에 있어야 했다.

파일 이름도 확인 대상이었다. Linux에서는 OfficeKey.txt와 Officekey.txt가 같은 이름으로 처리되지 않는다. Windows에서 옮긴 파일이라면 경로와 대소문자를 함께 맞춰야 했다.

실제 업로드 과정에서는 폴더 구조가 유지되는지도 확인했다. 개별 파일만 상위 폴더에 놓이면 프로그램이 기대하는 하위 경로와 달라질 수 있기 때문이다.

설치 원본은 필요한 폴더 구성을 유지해 옮기고, 실제 키 파일은 저장소와 공개 글에 넣지 않았다.

## 4. missing 목록이 사라지는지 다시 확인했다

필요한 원본을 옮긴 뒤 같은 API를 다시 확인했다. 현장에서 전달받은 최종 응답은 다음과 같았다.

```json
{
  "media": {
    "ready": true,
    "missing": []
  }
}
```

이제 서버가 검사하는 필수 파일이 준비된 상태였다. 관리자 화면에서도 셋업 버튼이 활성화됐고 작업을 요청할 수 있었다.

다만 이 응답으로 Office 설치와 Excel 실행, 정품 인증까지 확인한 것은 아니다. 이 단계에서 확인한 것은 서버가 배포에 필요한 파일을 찾았다는 사실이다.

## 다음에 같은 상황을 만나면

서버에 접속된다는 이유만으로 설치 준비까지 끝났다고 판단하지 않기로 했다.

```text
서버가 요청에 응답하는가?
        ↓
서버가 설치 원본과 설정 파일을 찾는가?
        ↓
Windows 클라이언트가 받아 실행하는가?
        ↓
Office 설치·Excel 실행·인증이 정상인가?
```

이번에는 두 번째 단계가 빠져 있었다. 서버 재시작부터 반복하기보다 무엇이 준비되지 않았는지 목록으로 확인하는 편이 문제를 좁히는 데 도움이 됐다.
