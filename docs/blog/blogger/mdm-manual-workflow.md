# DuctTape 개발 일지 — MDM 설치와 기기 등록을 나눠 생각하게 됐다

PC 환경을 설정하는 DuctTape에 MDM을 추가하는 작업을 진행했다. Office나 한컴뿐 아니라 다른 프로그램도 추가할 수 있도록, 관리자 화면에서 앱을 등록하고 클라이언트가 선택하는 구조를 만들던 중이었다.

이번 대상은 Argos MDM이었다. 기존에는 설치 파일을 PC로 가져가 setup.exe를 실행한 뒤, Windows 설정의 ‘회사 또는 학교 액세스’에서 ‘장치 관리에만 등록’을 선택하고 이메일과 공통 계정으로 등록했다.

처음에는 이 과정도 서버에서 요청하면 백그라운드로 끝낼 수 있을지 생각했다. 하지만 프로그램을 설치하는 일과 Windows 기기를 MDM 서버에 등록하는 일은 구분해야 했다.

## 설치 파일이 있다고 등록 방법까지 확인된 것은 아니었다

준비한 원본에는 setup.exe와 MSI가 있었다. MSI 정보를 읽어 제품과 버전을 확인했고, 일반 앱을 위한 MSI 설치 어댑터도 구현했다. 그렇다고 MSI만 실행하면 기존 setup.exe와 같은 결과가 나온다고 확인한 것은 아니었다. 실제 Argos 설치와 기관 계정 등록은 별도 검증이 남아 있었다.

Windows 설정 화면에서 버튼을 선택하고 계정을 입력하는 방법도 검토했다. 화면 자동화는 가능할 수 있지만, 현재 에이전트는 SYSTEM 권한으로 백그라운드에서 실행된다. 로그인한 사용자의 화면을 조작하려면 별도 구조가 필요하고, Windows 화면이나 인증 절차가 바뀌면 실패할 수 있다. 이번 작업에서는 화면 자동화를 구현하거나 시험하지 않았다.

## 먼저 줄일 수 있는 수작업부터 줄이기로 했다

당장의 목표를 다시 정했다. 기기 등록까지 무리하게 연결하기보다 설치 파일을 PC마다 들고 다니는 과정을 줄이는 쪽으로 정리했다.

Argos는 자동 설치 선택 대상에서 제외했다. 대신 관리자와 승인된 클라이언트 화면에서 설치 원본 ZIP을 내려받을 수 있도록 바꿨다. 사용자는 압축을 풀고 setup.exe를 실행한 뒤, 기기 등록을 수동으로 진행한다. 서버에서도 새로운 Argos 자동 설치 요청을 거부하도록 했다.

등록 URL과 계정 정보는 설치 파일에 넣지 않고 별도 설정 파일로 분리했다. 승인된 PC 사용자가 ‘등록 URL·계정 확인’ 버튼을 눌렀을 때만 표시한다. 표시된 정보는 숨기기 버튼, 탭 전환 또는 1분 경과 시 화면에서 제거한다. 이것은 이미 읽거나 저장한 정보를 회수하는 기능은 아니다. 공통 비밀번호를 설정했다면 승인된 사용자가 볼 수 있다는 점도 구분해야 한다.

## 테스트에서 다운로드 인증 문제도 확인했다

API 테스트에서는 인증되지 않은 요청과 승인되지 않은 PC의 접근을 막는지, 초안 상태의 파일을 내려받을 수 없는지, 자동 설치 요청이 차단되는지 확인했다.

브라우저 테스트에서는 다운로드가 진행되지 않는 문제가 나타났다. 다운로드 요청의 개발 모드 인증 처리와 필수 헤더가 기존 API 요청과 일치하지 않았다. 이를 수정한 뒤 다시 확인했다.

관리 앱 API 테스트 12개와 작업 큐·관리자 인증 회귀 테스트 13개가 통과했다. Chromium 테스트에서는 일반 앱 설치 흐름과 MDM ZIP 다운로드, 자동 설치 선택 비활성화, 등록 정보 표시와 숨기기를 확인했다. 테스트에 사용한 설치 원본과 작업 결과는 모의 데이터였다.

## 아직 확인하지 않은 부분

이 변경으로 실제 Argos 설치나 기관 MDM 등록을 완료한 것은 아니다. 변경 당시 Raspberry Pi 서버에 배포하지도 않았다. 수동으로 설치와 등록을 마쳤는지 서버가 자동 판정하는 기능도 없다.

이번에는 자동화 범위를 줄였지만, 무엇을 자동으로 확인할 수 있고 어디서 사람이 작업해야 하는지가 더 분명해졌다. 다음에는 전용 Windows PC에서 다운로드부터 수동 설치·등록까지 실제 절차를 확인해야 한다.
