# DuctTape 개발 일지 — 관리자 QR 도구와 기능 스위치를 붙였다

기존 QR 스크립트를 검토하면서, 처음부터 명단 업로드와 라벨 PDF까지 옮기기보다 입력한 값으로 QR을 만드는 화면부터 붙이기로 했다. 이번에는 Google API 연결 없이 가능한 서버 기능을 구현했다.

관리자에 ‘도구·기능 관리’ 화면을 추가했다. PC 목록의 ‘QR 만들기’를 누르면 해당 PC가 이미 보고한 시리얼을 가져온다. 입력값을 확인한 뒤 QR을 만들고 PNG로 내려받는다. 새 PC에 아직 시리얼 보고가 없다면 직접 입력해야 한다. 서버 자신의 장치 정보를 읽는 방식은 아니다.

사용자 이름 입력란도 두었지만 현재는 화면 메모다. 이름이 인쇄된 라벨이나 이름이 들어간 QR은 만들지 않는다. 기존 스크립트의 두 데이터 형식과 출력 순서가 달랐기 때문에, 우선 QR에는 입력값만 담도록 범위를 정했다.

## 서버 기능을 끄면 실제 요청도 막혀야 했다

QR 생성과 MDM 다운로드·등록 정보 확인을 각각 켜고 끄는 설정을 추가했다. 설정은 서버 DB에 저장한다. QR을 끄면 생성 API가 요청을 거부한다. MDM을 끄면 클라이언트 앱 목록에서 Argos를 숨기고 다운로드와 계정 정보 조회를 막는다. 이미 받은 파일이나 진행 중인 작업을 회수·취소하는 기능은 아니다.

임의 코드를 업로드하는 플러그인 시스템까지 만든 것은 아니다. 현재는 서버가 알고 있는 두 기능만 설정한다. 새 기능은 같은 권한 검사와 설정 규약에 맞춰 코드로 연결해야 한다.

## 테스트에서 PC 목록의 열 순서가 영향을 줬다

PC 목록에 QR 링크를 추가한 뒤 기존 관리자 UI 테스트가 실패했다. 기존 테스트가 PC 선택 버튼의 열 위치를 기준으로 동작하고 있었는데 새 열이 그 앞에 들어갔다. 기존 선택 열의 위치를 유지하고 도구 열을 뒤에 배치한 다음 다시 확인했다.

QR은 생성 응답만 확인하지 않고 실제 브라우저에서 PNG로 내려받아 독립 디코더로 읽었다. 모의 시리얼의 앞자리 0이 유지되는지, 한글과 특수문자가 원문대로 돌아오는지 확인하는 테스트를 추가했다. 사용자 이름은 QR 값에 섞이지 않도록 했다.

이번 화면은 서버에서 QR 행렬을 만들고 브라우저에서 PNG로 그린다. Windows 전용 폰트나 PDF·Excel 라이브러리는 넣지 않았다. QR 입력값과 이미지를 서버 파일이나 DB에 보관하지 않는다.

## 남은 확인

실물 탭북과 휴대폰 스캔, 라즈베리 ARM64 환경 배포, 라벨지 인쇄는 별도 확인이 필요하다. 라벨 PDF와 설치와 독립된 시리얼 수집은 후속 범위다. Blogger도 계정 연결 전이라 이번 글은 로컬 초안이며 자동 업로드한 결과가 아니다.
