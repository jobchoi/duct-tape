# Office가 없는 PC에서 왜 Office 제거가 실패했을까?

미니 PC에 Office와 한컴을 설치하려고 DuctTape의 셋업을 실행했다. 그런데 설치가 끝나지 않았다. 서버에서는 실패라고 표시됐고, 처음에는 어떤 문제인지 알 수 없었다.

이전에 탭북에서 사용하던 기능을 NUCBOX M8에서도 실행한 상황이었다. PC 형태나 Windows 환경의 차이를 의심할 수 있었지만, 먼저 실제로 어느 단계에서 멈췄는지 확인했다.

## 설치보다 앞선 단계에서 멈췄다

서버의 작업 기록을 확인하니 어제와 오늘 모두 같은 곳에서 실패했다.

```text
02_CheckOffice.ps1 완료
03_RemoveOffice.ps1 실패
```

한컴이나 새 Office 설치가 실패한 것이 아니라, 기존 Office를 제거하는 단계에서 멈춘 것이었다.

서버에 기록된 최종 종료 코드는 1이었다. 이것만으로 설치기의 원인을 알 수는 없어서 클라이언트의 작업 로그를 확인했다.

```text
PROCESS_EXIT: -1
03 : INSTALL_PROCESS_FAILED
```

여기서도 실패 여부만 알 수 있었다. Windows 임시 폴더에서 실패 시각과 맞는 Office 상세 로그를 찾아 확인했다.

## 서비스가 없다는 메시지

Office 로그에서 핵심 메시지가 나왔다.

```text
Downsell attempted without active ClickToRunSvc
```

ClickToRunSvc 서비스 조회 결과도 아무것도 나오지 않았다. 처음에는 Office가 불완전하게 남은 상황일 수도 있다고 생각했다.

그런데 이 PC는 처음 설치하는 장비였고, 사용자가 확인한 바로는 Office가 없었다.

여기서 질문이 바뀌었다.

**Office가 없는 PC에서 왜 제거 작업을 먼저 실행했을까?**

## ‘설치 필요’와 ‘제거 필요’를 같은 것으로 처리했다

코드를 확인하니 목표 Office 버전이 없으면 상태를 ‘설치 필요’로 정하고 있었다. 그 자체는 자연스러웠다.

문제는 다음 제거 단계에서도 같은 상태만 보고 제거기를 실행했다는 점이었다.

```text
목표 Office 없음
  → 설치 필요
  → 기존 Office 제거 실행
  → 서비스 없음으로 실패
  → 새 설치에 도달하지 못함
```

목표 프로그램이 없다는 사실과, 지워야 할 기존 프로그램이 있다는 사실은 서로 다른 조건이었다. 코드에서는 그 둘을 구분하지 못했다.

서버 원본의 remove.xml도 확인했다. 제거 설정은 들어 있었고 설치용 Add 요소는 없었다. XML 이름이나 미니 PC 모델만으로 원인을 단정할 문제가 아니었다.

## 제거할 제품이 있는지 먼저 확인하도록 수정했다

제거 단계에서 기존 Office의 흔적을 별도로 확인하도록 바꿨다. Windows의 32비트·64비트 제거 목록, ClickToRun 구성, 서비스 상태를 확인한다.

- 제품과 구성 흔적, 서비스가 모두 없으면 제거를 건너뛴다.
- 기존 흔적이 있는데 서비스가 없으면 구체적인 오류를 남기고 중단한다.
- 서비스가 중지돼 있으면 그 상태를 알린다.
- MSI 방식의 기존 Office가 확인되면 별도 제거가 필요하다고 알린다.
- 기존 ClickToRun 제거 조건이 맞으면 원래 제거 절차를 실행한다.

서비스가 없다는 이유만으로 모든 경우를 통과시키지는 않았다. 실제 제품이 불완전하게 남은 PC도 있을 수 있기 때문이다.

## 어디까지 확인했는가

Windows PowerShell에서 설치기·서비스·레지스트리를 모의 처리해 빈 PC, 기존 제품, 서비스 누락·중지, MSI 제품, 조회 오류, 설치기 실패 등의 분기를 검증했다. 이 시험에서는 실제 Office를 설치하거나 제거하지 않았다.

서버 반영과 실제 미니 PC 설치는 별개의 확인이다. 서버에서 새 파일을 배포해도 이미 PC에 설치된 에이전트 파일이 자동으로 바뀌지는 않는다. 최신 에이전트를 적용한 뒤 해당 PC에서 셋업을 다시 실행해야 한다.

이 글의 수정으로 미니 PC의 Office 설치가 끝났다고 기록할 수는 없다. 현장 재시도와 실제 설치 결과 확인은 다음 단계다.

## 이번에 배운 것

처음에는 장비나 Windows 환경의 차이를 떠올렸지만, 로그를 따라가면서 확인한 것은 코드의 조건 하나였다.

**‘설치해야 한다’는 사실만으로 ‘먼저 제거해야 한다’고 판단해서는 안 됐다.**

이번에는 서버의 실패 상태, 에이전트 종료 코드, Office 상세 로그, 서비스 조회, 실제 코드 순서로 확인했다. 각 기록이 알려주는 범위가 달랐고, 그 결과를 함께 봐야 다음 확인 대상을 좁힐 수 있었다.
