# 블로그 작업 UI 후속 계획

2026-10-22 사용자 의견을 기록한다. 선행 작업인 기존 글 검토·남은 글 업로드를 먼저 마무리한다. 이번에 UI 구현이나 코드 리뷰를 수행한 것은 아니다.

## 분리 방향

블로그 편집·발행 도구는 PC 설치 프로그램 DuctTape와 목적·계정·권한·운영 주기가 다르므로 별도 도구/프로젝트로 발전시키는 것을 우선 제안한다. 현재 tools/blogger는 서버와 의존성을 분리한 CLI다. 새 프로젝트로 추출할 경우 코드·테스트·운영 안내를 함께 옮긴다. DuctTape 메뉴에 진입점이 필요하면 별도 서비스로 여는 링크/탭을 두고 인증 토큰·DB·런타임을 공유하지 않는다. 실제 저장소 분리나 탭 추가는 아직 하지 않았다.

QTP 헌장은 editorial/qtp에서 편집 기준으로 참조하며 이 도구의 구현 명세와 혼합하지 않는다.

## 초기 UI 범위 제안

연결 상태 확인 → 작업 기록/기존 원고 선택 → Blogger 일지·티스토리 매뉴얼 구분 → 초안 편집/미리보기 → 라벨 확인 → 사용자 검토 확인 → Blogger 초안 업로드 → 결과/오류/중복 확인.

AI 집필과 예약 공개는 초기 필수 기능으로 넣지 않는다. 새 Google 연결을 웹 서버 콜백으로 처리하면 현재 데스크톱 OAuth와 별개로 웹 클라이언트·리디렉션·세션/요청 위조 방지를 설계한다. 티스토리는 공식 글쓰기 API가 종료되어 파일 내보내기 중심으로 구분한다.

## 구현 전후 리뷰와 기록

기존 CLI의 인증/토큰 보관·오류/재시도·업로드 중복·원격 수동 편집 보존부터 코드 리뷰한다. UI 구현 후 권한 경계·XSS·파일 범위·외부 API 실패·토큰 만료·중복 업로드·내용 변경 후 재검토를 테스트한다. 실제 공개는 작성자가 승인한 원고 버전으로만 진행하는 원칙을 유지한다.

확인한 문제·설계 선택·수정·테스트 결과를 블로그 일지로 남기고 사용 절차는 별도 매뉴얼로 작성한다. 계획을 실제 코드 리뷰나 검증 결과인 것처럼 게시하지 않는다. 원자료를 외부 AI에 전달할 때 인증 파일·토큰·키·민감 로그를 제외한다.

## 우선순위

1. 현재 게시 요청 완료 및 결과 기록.
2. 블로그 도구 코드 리뷰와 요구사항 정리.
3. 별도 서비스/프로젝트 경계와 OAuth 방식 확정.
4. 최소 UI 구현·테스트·실제 초안 업로드 확인.
5. 검증된 과정의 일지·매뉴얼 작성.

새 저장소·새 채팅에서 시작할 때는 [독립 인수인계 문서](NEW_PROJECT_HANDOFF.md)를 먼저 따른다. 현재 구현과 제안을 구분해 정리했다.
