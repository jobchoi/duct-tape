# QTP AI 협업 운영

2026-10-21. [헌장](CHARTER.md)을 실행하기 위한 절차다. AI 오케스트레이션 구현 사양이나 이미 연결된 서비스 목록은 아니다.

## 역할

| 역할 | 책임 | 결과물 |
| --- | --- | --- |
| 작성자 | 질문·원자료·경험 제공, 미해결 의견 판단, 최종 공개 결정 | 작업 목적·확인된 경험·원고 승인 |
| 연구 지원 | 질문 구조화, 근거 탐색, 반례·논리 비약 확인 | 근거·가설·미확인 목록 |
| 작성 지원 | 원자료 범위에서 글 구조와 초안 작성 | 출처/작업 기록이 연결된 초안 |
| 편집 검토 | 독자 관점에서 구조·표현·재현 조건 확인 | 수정 제안 |
| 원칙 검토 | 사실/추정·작성자 경험·검증 범위·공개 기준 점검 | 문제 목록·발행 권고 |

ChatGPT·Gemini·Claude 등은 사용 가능한 도구의 예이며 고정 담당자가 아니다. 유료 구독 여부보다 실제 도구 접근, 지원 기능, 입력 자료 처리 조건, 비용·품질에 따라 배정한다. 구독으로 API나 다른 서비스 사용 권한까지 제공된다고 가정하지 않는다. 실제 도구 선정 시 제공 조건을 확인한다.

## 최소 절차

질문/목적 → 근거·작업 기록 확인 → 초안 → 작성자 검토 → 초안 업로드 또는 공개.

짧은 일지는 한 도구와 작성자 검토로 끝낼 수 있다. 초안 업로드는 공개와 구분한다. 작업 매뉴얼은 감상보다 적용 조건·실행·검증·복구를 우선한다.

## 추가 검토

기술적 단정, 원인 미확인, 교육 효과 주장, 타인/기관 정보, 재현 절차의 변경 등은 근거 확인과 추가 리뷰를 적용한다. 독립 검토가 필요하면 작성자의 결론을 그대로 정답으로 주입하지 않고 같은 근거를 보고 비판하도록 요청한다. 리뷰가 다르면 투표로 결론 내리지 않고 근거를 재확인하거나 미확인으로 남긴다.

## 수동 협업

작성자가 필요한 역할을 골라 최소 자료만 전달한다. 모든 AI 서비스를 순회하지 않는다. 각 리뷰의 새 지적만 원고에 반영하고, 수정 이유와 남은 쟁점을 짧게 기록한다.

## 도구/API 기반 오케스트레이션

연결 도구가 준비되면 원자료 선택 → 초안 → 필요한 리뷰 → 수정 → 작성자 확인 대기로 연결할 수 있다. 다음 실행 정보는 헌장이 아니라 도구 설정/운영 기록으로 관리한다.

- 역할별 모델/도구, 비용·실행 시간·재시도 상한, 외부 전송 허용 자료.
- 원자료 기준 시점, 원고 ID·버전, 단계별 결과와 미해결 지적.
- 결과 형식: 초안, 주장별 근거, 확인 필요 목록, 수정 제안. 내부 추론 전체나 토큰·비밀값을 보관하지 않는다.
- 실패/한도 초과 시 중단하거나 미완료 상태로 보관한다. 검토를 통과했다고 꾸미지 않는다.
- 원고가 달라지면 다시 검토한다. 공개 요청은 승인한 원고 버전과 연결하고 중복 게시를 방지한다.

자동 검토 도구는 작성자 승인까지 대체하지 않는다. 여러 AI의 사용·병렬 실행·유료 기능은 필요할 때 운영 구성을 바꾸는 선택지이지 매번 수행할 의무가 아니다.

## 상태

작성 중 → 검토 중 → 작성자 확인 대기 → 승인된 초안 → 업로드됨(초안) → 공개됨.

개발 기능의 테스트 통과와 글의 검토 통과를 별도로 기록한다. 업로드 도구가 없거나 인증이 끝나지 않으면 로컬 초안 상태로 유지한다.
